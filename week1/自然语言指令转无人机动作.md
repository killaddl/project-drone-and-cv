# 自然语言指令转无人机动作：方案、库与协议整合版

> 前置说明：底层飞控统一协议为 **MAVLink**；MAVSDK 是 MAVLink 的上层封装SDK，并非协议；适配机型：搭载PX4/ArduPilot飞控（Pixhawk、SITL仿真机、DIY开源无人机）

## 一、动作粒度

| 粒度 | 输出形态 | 特点 |
|---|---|---|
| 原子飞控指令 | 速度/姿态/油门/起飞降落（MAVLink 指令、setpoint） | 频率高、需要飞控闭环，语义最底层 |
| 技能调用 | 调用封装好的函数/接口（`goto`、`follow`、`take_photo`） | 动作空间封闭、安全可控，工程上最常用 |
| 航点/轨迹 | 一串带约束的 waypoint 或多项式轨迹 | 交给现有航迹跟踪器执行，便于审查 |
| 端到端动作 | 模型直接输出动作向量或动作 token | 无需中间接口，但不可解释 |

## 二、具体实现方式 + 配套库、协议栈

### 1. 规则/模板 + 意图识别与槽位填充
传统 NLU 路线：训练意图分类器 + 槽位抽取（BERT/CRF ），把`飞到 A 点上方 50 米`解析为 `{intent: goto, target: A, altitude: 50}`，再用模板拼成结构化指令或 MAVLink 命令。
- 优点：可解释、低延迟、可离线，误触发可控。
- 缺点：意图集合靠人工穷举，自由表述和复合指令覆盖差。
- 适用：语音遥控、应急指挥等对确定性要求高的场合。
- 技术栈：pytorch/transformers；飞控：`mavsdk`；协议：MAVLink

### 2. 语义解析到形式化中间表示，再交给规划器
自然语言先转成机器可验证的中间语言——PDDL（域+问题）、领域专用语言（DSL）、行为树、状态机——再由经典规划器或行为树引擎生成动作序列。
典型做法：LLM 生成 PDDL 域与问题描述（SPAR），或生成行为树 XML。
- 优点：计划可静态检查、可证明可行性、出错可定位。
- 缺点：域建模成本高，符号表示与真实感知的“接地”较弱，环境一变就得改域。
- 技术栈：`py_trees`（行为树）、`transition`（简单状态机）、PDDL规划器；LLM校验：`instructor`；飞控：`mavsdk`；协议：MAVLink

### 3. LLM 作为解析器，输出结构化任务计划
LLM 只负责“读懂 + 拆分”，把指令变成带字段的任务计划（JSON：任务类型、POI、约束、优先级），后续由专门模块执行。代表工作 NeLV：`LLM-as-Parser` → 路线规划 → 路径规划生成航点 → 控制平台执行 → 飞行监控。
- 优点：不改飞控、不训练模型，能处理中长程多任务（多机巡逻、多点配送、多跳转场）。
- 缺点：依赖输出 schema 约束与严格校验，LLM 仍可能给出物理上不可行的计划。
- 技术栈：httpx/LLM官方SDK、`instructor`（Pydantic结构化校验）；视觉侧：`opencv`、`ultralytics`、`torch`；飞控：`mavsdk`；协议：MAVLink

### 4. LLM 直接生成代码/API 调用（code-as-policy）
指令 → Python 脚本（`mavsdk` / ROS 接口）→ 执行。GSCE框架依靠准则、技能API清单、硬约束、示例提升生成成功率。
- 优点：表达力最强，能组合出没预定义过的动作序列。
- 缺点：会编造不存在的API、参数越界；必须沙箱执行+静态检查+约束注入，不能裸跑。
- 技术栈：httpx/LLM官方SDK、`instructor`；飞控：`mavsdk`；协议：MAVLink

### 5. 工具调用 + 技能库接地（SayCan 式）
预定义一套技能库（起飞、航点、跟随、拍照、返航……），LLM负责选技能、填参数，用可行性打分模型筛选；搭配ReAct“观察—思考—动作”循环逐步推进。
- 优点：动作空间封闭，安全性最好，最容易落地。
- 缺点：能力上限由技能库决定，遇到库里没有的动作就退化。
- 技术栈：httpx/LLM官方SDK、`instructor`；状态调度：`py_trees`；飞控：`mavsdk`；协议：MAVLink

### 6. 多模态接地：把指代解析成目标点
先由视觉模型（检测/分割/深度）定位目标，估计三维位置或相对方位，再把目标点交给位置环控制；多模态大模型也可直接输出目标框、相对位移。
- 优点：解决自然语言中的指代与空间关系，纯文本解析无法做到。
- 缺点：误差来自感知与标定，目标遮挡、描述歧义时容易失败。
- 技术栈：`opencv`、`ultralytics`、`torch`；飞控：`mavsdk`；协议：MAVLink

### 7. 视觉语言导航（VLN）：指令 → 逐步路径
单步输入`指令 + 当前视角图像`，输出下一步航向/高度/速度或下一个航点。AerialVLN、SkyVLN属于这类，SkyVLN先用LLM抽取地标子目标，再用NMPC底层跟踪。评测指标：SR成功率、NE导航误差、OSR超出路径比例。
- 优点：端到端按语言找路，不需要预先建图。
- 缺点：依赖大规模仿真数据，仿真实机gap明显，长指令容易迷失。
- 技术栈：`torch`、`ultralytics`；飞控：`mavsdk`；协议：MAVLink

### 8. VLA端到端视觉动作模型（Vision-Language-Action）
语言+视觉联合编码，直接回归动作向量，无显式解析、规划、接口层；推荐SmolVLA，OpenVLA不推荐。遥感/仿真数据采集使用LeRobot。
- 优点：省去手工接口，理论上可习得难以建模的操作技巧。
- 缺点：数据饥渴、机载算力压力大、可解释性与可验证性最弱，故障难以归因。
- 技术栈：SmolVLA、LeRobot；`torch`；飞控：`mavsdk`；协议：MAVLink

### 9. 语言条件策略学习（模仿学习 / 强化学习）
指令编码为条件向量，训练策略网络输出动作；数据来自遥操作示范或者仿真RL，扩散策略、ACT都可用于语言条件轨迹生成。
- 优点：和机体动力学贴合最好。
- 缺点：任务窄，泛化到新场景需要新增数据，训练成本高。
- 技术栈：`torch`；仿真环境；飞控：`mavsdk`；协议：MAVLink

### 10. 语音作为前置入口
语音仅为输入入口，ASR转文本后可接入上面任意路线；也存在端到端语音模型直接输出指令。工程上一般增加唤醒词、说话人校验、指令确认，规避误触发。
- 技术栈：ASR库（whisper等）；后续链路同上；协议：MAVLink

## 三、横向对比

| 方式 | 输出 | 是否需训练 | 可解释/可验证 | 泛化能力 | 典型场景 |
|---|---|---|---|---|---|
| 意图+槽位 | 结构化指令 | 小模型需训练 | 强 | 弱 | 语音遥控、应急 |
| 形式化中间表示 | PDDL/行为树/DSL | 不需要 | 最强 | 中 | 任务级规划、多机协同 |
| LLM 解析器 | 任务计划 JSON | 不需要 | 中 | 强 | 中长程任务编排 |
| 代码生成 | 脚本/API 调用 | 不需要 | 中（靠约束） | 强 | 快速搭原型 |
| 工具调用接地 | 技能+参数 | 可选 | 强 | 中 | 产品化落地 |
| 多模态接地 | 目标点/位姿 | 需视觉模型 | 中 | 中 | “飞到那个东西旁边” |
| VLN | 航点/速度 | 需大量数据 | 弱 | 中 | 无图导航 |
| VLA | 动作向量 | 需大量数据 | 最弱 | 待验证 | 研究前沿 |
| 语言条件策略 | 动作 | 需示范/仿真 | 弱 | 弱 | 特定任务 |

## 四、工程主流组合架构

工程通用4个保障机制：
1. **动作空间封闭化**：预先定义技能库、API白名单，限制模型调用范围，禁止自由生成未知动作
2. **输出约束**：JSON schema、语法约束解码、参数上下限校验，拦截格式错误、数值越界
3. **执行前校验**：几何可行性、电量、地理围栏、禁飞区检查，必要时仿真预演
4. **人在回路与回退**：高危动作二次确认，异常自动降级至悬停/返航

## 五、小结

路线分为两大分支：
1. **符号化路线**：语言转为意图槽位、DSL、PDDL、任务计划、技能调用；可控、可验证，但能力上限由人工定义的规则决定，是目前工程落地主流；
2. **端到端模型路线**：VLN、VLA、语言条件策略；泛化潜力大，但数据成本高、可解释差，大多停留在研究演示阶段。

当前最优工程方案：**LLM高层解析 + 封闭技能库 + 视觉接地 + 传统飞控闭环**。

## 六、配套库、协议汇总（Q3原始要点）

> 底层协议统一为 MAVLink

1. **LLM生成结构化指令或代码**
    - LLM：官方SDK或者 httpx 直接发送请求，`instructor` 校验
    - 视觉执行侧：`opencv`，`ultralytics`，`torch`
    - 飞控：`mavsdk`

2. **VLA端到端模型**
    - 模型：SmolVLA，OpenVLA（不推荐）
    - 遥感数据采集：LeRobot
    - 飞控：`mavsdk`

3. **结构化执行图，专家规则检验**
    - 状态机库：`transition`，`py_trees`
    - LLM生成：`instructor`
    - 飞控：`mavsdk`

> 通信承载层：MAVLink可跑在UDP（仿真/WiFi数传）、Serial串口、TCP上；推荐机型：PX4/ArduPilot飞控无人机、Pixhawk硬件、SITL仿真
